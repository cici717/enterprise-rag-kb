# 项目演示脚本

## 演示前准备

```powershell
cd E:\ai-rag-kb
.\run_backend.ps1
```

另开终端：

```powershell
cd E:\ai-rag-kb
.\run_frontend.ps1
```

打开 http://localhost:8501。

如果演示数据库是空的，可以在后端启动后执行：

```powershell
cd E:\ai-rag-kb
.\.venv\Scripts\python.exe scripts\seed_demo.py
```

## 3～5 分钟演示流程

### 第一步：介绍项目

“这是一个企业知识库 RAG 问答系统。它解决两个问题：一是让用户直接问文档，而不是自己翻文档；二是让回答有引用来源，降低大模型幻觉。”

### 第二步：展示文档管理

打开左侧栏，展示：

- 后端连接状态
- 文档数量
- Chunk 数量
- 文档列表
- 上传入口

说明支持 PDF、Word、TXT、Markdown。

### 第三步：上传文档

上传一个 PDF 或 Word 文件，点击“上传并入库”。

说明后端会执行：

解析 → 切分 → Embedding → 写入索引

### 第四步：提问验证

依次提问：

1. “迟到超过三十分钟怎么处理？”
2. “年假满三年不满五年有多少天？”
3. “报销申请一般要在费用发生后多久提交？”
4. “企业版智能客服支持什么部署方式？”
5. “知识库数据会不会用于训练模型？”

展示回答下方的“引用来源”，说明每条引用包含文件名、页码、相关度和片段内容。

### 第五步：展示流式输出

指出回答是逐字出现的，后端使用 SSE，先返回引用，再逐 token 返回回答。

### 第六步：展示接口文档

打开 http://localhost:8000/docs，介绍：

- `POST /api/documents/upload`
- `POST /api/chat`
- `POST /api/chat/stream`
- `GET /api/conversations`
- `POST /api/feedback`

### 第七步：说明工程化

- 有单元测试
- 有评测脚本
- 有 Docker 配置
- 支持离线 Mock 模式
- 可以切换真实大模型

## 录屏建议

- 录屏分辨率：1920×1080
- 时长：3～5 分钟
- 先展示架构图，再演示功能
- 重点录制引用来源和流式输出
- 最后用一句话总结项目价值

## 演示结束语

“这个项目让我完整实践了 RAG 的文档处理、检索、生成、引用和评测流程。它不只是一个聊天界面，而是包含后端接口、数据存储、流式输出和部署配置的完整应用。”
